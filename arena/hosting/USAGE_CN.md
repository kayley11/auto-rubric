# AutoRubric 使用说明

网址：**https://auto-rubric.kayley1026lzt.chatgpt.site**

平时直接打开网址即可，不需要每次安装环境或重新部署。已有研究结果可公开浏览；生成回答、评分和保存复核需要登录，并且本机后端和隧道正在运行。

## 1. 先确认要做什么

| 目的 | 从哪里开始 | 是否需要登录和本机在线 |
| --- | --- | --- |
| 看已有实验、跨模型结果、原始对话和评分理由 | 导航中的 **Interview study** | 不需要；公开快照在后端离线时也可浏览 |
| 输入病例，生成或粘贴回答，再评分 | **New evaluation → Written case** | 生成、评分和保存需要 |
| 让模型主动问诊，再评分 | **Patient interview** | 需要 |
| 对已有研究回答独立评分、确认信息要求 | **Review first** 或 **Review this case** | 浏览材料可不登录；保存需要 |

公开研究页展示已发布的批次，不会自动加入刚产生的新评估。

## 2. 登录和账号

点击右上角 **Sign in**。

- **R01**：可生成回答、评分、保存复核。
- **R02**：只可保存复核，不能调用模型。
- 密码保存在本机 `arena/.data/public-access/ACCESS.txt`，没有上传 GitHub。只向获准使用相应账号的人提供其登录资料。
- 登录有效期为 8 小时，过期后重新登录。退出用 **Sign out**。

新评估和复核按账号保存。R02 可以复核公开研究材料，但不能直接打开 R01 的私有新评估。需要别人查看新评估时，先导出病例、回答或空白复核表发送给对方；私有运行链接不能代替材料导出。

## 3. 评估一份书面病例

1. 选择 **Written case**。在 **Load a prepared case** 载入病例，或在 **Case facts** 粘贴自己的病例信息。
2. 展开 **Task & reference**，写清受众、任务要求和可供模型使用的既有对话。评分参考单独放在 Reference 中，不要混进 Case facts。参考尚未完成临床确认时，保留 **Draft — awaiting confirmation**。
3. 选择 **Generate answer**，或用 **Paste answer** 放入已有回答。生成模型会看到病例、任务和提供的对话，不会看到评分参考或隐藏病例资料。
4. 展开 **Settings**，确认回答模型、评分模型和评价项。选择 **Original rubric**，或 **Proposed D3a / D5c · awaiting confirmation**。新版只替换 D3a 和 D5c，其余条目保持原版。
5. 运行评分，查看各条目的名称、分数、理由和证据。需要人工判断时进入复核；最后从 **Export** 下载材料。

使用新版 D5c 时，需要提供实际提出的问题、实际返回的资料和候选必要信息清单。可通过 **Reuse a saved interview** 载入已有记录。不要用“计划询问什么”冒充已经提出的请求，也不要把隐藏结果写成已获得的信息。仅有最终回答、没有问诊证据时，不要强行评价信息获取。

评分失败时使用 **Retry**：保留当前回答和已完成条目，只继续失败部分。只有想研究另一份回答或另一种输入条件时，才新建评估。**API configured** 只表示已配置凭据，不保证 KCL 每次请求都成功。

## 4. 运行一次患者问诊

1. 打开 **Patient interview**，选择现有八例之一。
2. 确认提问模型、评分模型和规则版本，再启动问诊。
3. 模型最多提问六轮；固定事实控制器按实际问题返回允许提供的信息。检查资料保留相应住院和时间背景。
4. 问诊结束后查看实际获得与遗漏的信息、最终回答，再选择 **Score D3a and D5c**。

D3a 评价模型如何概括已经收到的信息；D5c 评价它是否及时请求候选清单中的必要信息。候选要求、替代请求和期限继续标为 **awaiting confirmation**。

## 5. 人工复核和导出

- 做独立评分时，先进入 **Review first**，不要先打开机器分数和理由。先保存 D3a，再查看 D5c 所需的评审资料。完成后才显示机器对照；如果此前已看过结果，应如实记录。
- **Clinical decisions** 用于记录某项信息是必要、有帮助还是不需要，以及可接受替代、最晚提问时点和理由。浏览到候选清单不等于已经确认，只有完成实际判断后才能记录 confirmed。
- **Export** 汇总简版材料、空白复核表、完整 raw 输出，以及可用的 TXT、JSON、CSV。需要对方独立评分时，发病例、任务、回答和空白表，避免提前给出机器判断。
- 新结果保存在本机 `arena/.data/public-access/records/members/`。公开下载会去除历史姓名标注；原始研究档案和旧结果保留。

## 6. 电脑睡眠、重启或出现 offline 时

| 情况 | 怎么处理 |
| --- | --- |
| 电脑、后端和隧道一直在运行 | 直接打开网址、登录并使用；不用重新启动服务 |
| 页面显示 **Evaluations offline** | 仍可看公开研究结果；先检查主机联网和后端进程 |
| 只是网络暂时断开，隧道进程没有退出 | 恢复网络后刷新页面，检查是否重新在线 |
| 电脑重启，或后端进程退出 | 恢复受保护的后端，保留现有本机配置和结果目录 |
| 隧道进程重启 | 新的临时隧道地址需要写入 Sites 的 `BACKEND_ORIGIN` secret，再重新部署已有保存版本；公开网址不变 |

离线时，保留登录 Cookie 的浏览器也可继续查看公开研究。**Recent evaluations** 可能暂时为空，因为本机私有记录不可读取；这不表示结果被删除，后端恢复后刷新即可。

**电脑开机并不代表后端和隧道已经启动。** 当前没有设置开机自启。恢复时可以直接让 Codex 执行：

> 恢复 AutoRubric 公开网站的本机后端和受保护隧道；复用现有账号、秘密配置和 Sites 项目，更新后端连接，保留所有结果，并验证登录和权限。

不需要把密码或 API key 发到聊天里，也不需要重新创建网站。维护时复用项目 `appgprj_6adfdc1603988191a795a461d19f5914`。本机原始界面 `http://127.0.0.1:8765` 与公开网站不同；运行 `./run-ui.sh` 本身不能恢复公开网站的受保护连接。

## 7. 分享和保存

- 只看研究结果：发公开网址即可。
- 需要在线复核：私下提供相应复核账号，并指出要看的病例或批次。
- 需要调用模型：由获准的评估账号操作，同时保持主机、后端和隧道运行。
- 需要保存到 GitHub：先检查导出内容，再同步选定的公开实验和验证材料。`.env`、`ACCESS.txt`、`config.json` 和整个 `.data` 私有目录不上传。

部署方式和已验证的行为见 [部署说明](README.md) 与 [验证记录](../validation/20261026-public/README.md)。
