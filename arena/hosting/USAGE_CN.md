# AutoRubric 使用说明

网址：**https://auto-rubric.kayley1026lzt.chatgpt.site**

平时直接打开网址即可，不需要每次安装环境或重新部署。已有研究结果可公开浏览；生成回答、评分和保存复核需要登录，并且本机后端和隧道正在运行。

## 每次启动：重启电脑后也只需这三步

1. 保持这台 Mac 开机联网，在 Finder 中双击项目里的 **[启动AutoRubric.command](../../启动AutoRubric.command)**。工作目录 `毕设` 下也放了同名快捷入口，两者作用相同。
2. 等待窗口显示 **READY: https://auto-rubric.kayley1026lzt.chatgpt.site**。这表示公开页面和评估后端都已通过检查；脚本会自动打开网站。可以按回车关闭终端窗口，服务继续在后台运行。
3. 在网站点击 **Sign in**，使用原来的账号和密码。看已有病例和模型结果进入 **Case review**；新建评估进入首页 **New evaluation**。

重复点击会复用已经运行的恢复服务。后端退出会重新启动；隧道退出会重新建立连接并登记新地址，**公开网址不变，不需要重新部署**。普通断网会在恢复网络后继续尝试连接。

启动器不会修改 API key、重新创建账号或清空结果。它不会在开机时自行运行；每次重启并登录电脑后双击一次即可。

## 1. 先确认要做什么

| 目的 | 从哪里开始 | 是否需要登录和本机在线 |
| --- | --- | --- |
| 看已有实验、跨模型结果、原始对话和评分理由 | 导航中的 **Case review**，选择公开文献病例或登录后的 **Workspace cases** | 不需要；公开快照在后端离线时也可浏览 |
| 输入病例，生成或粘贴回答，再评分 | **New evaluation → Paste a case / Import cases** | 生成、评分和保存需要 |
| 对回答的全部所选条目独立评分 | **Review first** 或 **Review this answer** | 浏览材料可不登录；保存需要 |

公开文献病例继续在原渠道展示。新导入和新建的病例保存在后台，在 **Case review → Workspace cases** 中查找；**Saved evaluations → Open comparison** 可重新打开整批比较表。新增病例不会自动公开给未登录访问者。

## 2. 登录和账号

点击右上角 **Sign in**。

- **Account ID：workspace**，普通共享账号，原密码不变，可生成、评分、复核和导出；不能修改底层 rubric。
- 密码沿用原 R01 管理员密码。原登录信息保存在本机 `arena/.data/public-access/ACCESS.txt`，不在公开网页或代码中。
- **Account ID：rubric-editor** 为授权编辑账号，与 workspace 使用同一病例和结果。专用密码保存在本机 `arena/.data/public-access/RUBRIC_EDITOR_ACCESS.txt`。只有该账号能进入 **Higher-level decisions** 修改 rubric 或确认必要信息要求。修改保存为新版本，旧结果不变。
- 原 R01／R02 登录入口已停用；原结果目录和配置备份保留，记录已复制到共享空间。
- 登录有效期为 8 小时，过期后重新登录。退出用 **Sign out**。

共享账号中的新评估与复核由使用者共用，公开访问者仍看不到这些私有记录。复核时填写短代码（如 **CLINICIAN_A** 或 **R03**）；代码是自行填写的标识，不是单独认证的身份。已保存的复核和先前查看机器结果的记录仍保留。

## 3. 评估一份书面病例

1. 首页有 **Paste a case** 和 **Import cases** 两个入口。已有本地病例和历史模型结果统一在 **Case review** 查看。
2. 在最前面的 **Rubric & models** 选择 rubric、回答模型和评分模型。回答模型可单选或多选；目前 rubric 目录只有临床推理 rubric。**Assessment items → Choose items** 选择参与评分的条目，支持 **Select all** 和 **Clear selection**；**View definitions** 查看完整评分定义。新建空白评估默认使用标注日期的当前研究版本；如需重复或比较旧实验，展开 **Advanced settings** 选择历史版本。
3. 页面自动生成 **Case code**，不需要为病例取名。同一病例的不同模型结果共用编号。填写 **Original source**（可选，论文链接、DOI 或引文），再粘贴病例和任务；参考和既有对话按需展开。参考单独交给评分器，继续标为 **awaiting confirmation**。
4. 单选一个模型时，生成回答后可编辑，再评分。多选模型时，点 **Compare selected models**，检查预览后点 **Generate & compare**。也可以选择 **Paste an existing answer**，只评价已有回答。
5. 生成回答后仍可选择评分条目，再点 **Evaluate answer**。评分完成后，入口变为 **View item results**，跳到逐项分数和理由。选择条目决定哪些项目参与评分，并不只是筛选已完成结果。结果逐项显示，不计算总分；人工评分与自动评分分别保存。

左侧 **Saved evaluations** 打开可搜索的已保存记录表，可继续未完成的评分或查看结果。**Answer ready** 表示回答已保存、评分尚未完成；**Items assessed** 是评分进度，不是临床分数。历史 **Deployment check** 是上线流程验证记录，保留在单独的 **Technical checks** 标签页，不混入默认评估列表。

普通书面病例只需病例事实、任务和可选的评分参考。当前界面不提供患者问诊模式；历史输入、对话和完整输出仍保留。D5c 的必要信息要求和专项争议放在 **Higher-level decisions** 中核对，不混入普通病例输入。

逐项分析、结果详情和独立人工复核旁有 **Case details** 栏，电脑宽屏下固定在右边；可切换 **Case / Task / Answer**。**Case** 包含现有的描述、受众、任务类型、完整事实、既有对话、实际问题与返回记录、来源及原文位置；较长内容可在卡片内滚动。独立复核不显示额外来源描述和评分参考。小屏幕可展开右下角卡片。已评分的内容只读；点 **Edit as a new evaluation** 复制后修改，原结果保留。修改病例事实或任务后会分配新编号。

批量运行时保持标签页打开。超时或临时服务错误会移到队尾，最多自动重试两次；其他病例继续运行。反复失败的项目会明确列出，可稍后重试，已完成的回答和评分不会重复生成。单个评分失败时使用 **Retry**：保留当前回答和已完成条目，只继续失败部分。只有想研究另一份回答或另一种输入条件时，才新建评估。**API configured** 只表示已配置凭据，不保证 KCL 每次请求都成功。

### 批量导入

下载示例 CSV，或上传 CSV／JSON／JSONL。每行提供 facts 和 task；没有 task 的行使用公共任务。每行自动获得编号，title 不必填写；可增加 case_number（保留原文件编号）、answer、reference、source、history。已有 answer 的行只在 **Provided answer** 列评分一次；其余行由每个所选模型分别生成并评分。

导入后先预览，可修改或排除病例。确认模型、rubric、版本和评价项后，点 **Start batch**。结果表第一列是病例编号，后面是各回答模型的逐项分数和主要发现。点单元格可读完整输出。表内短评摘自最低数值评分项的评分理由；完整理由以弹窗中的记录为准。

**Pause after this evaluation** 在当前评估结束后暂停，**Resume batch** 从各单元格已保存的 run 继续，不重做完成项。同一标签页刷新后能恢复进度；已保存结果保留在工作空间。运行时保持标签页打开。**Export results** 提供对照 CSV 和完整 JSON。新版 D5c 的 JSON 输入仍需实际 interview 和 requirements。

### 阅读已有结果

进入 **Case review**，选病例。表格包括原五个模型和 Qwen 的已保存结果；点击任一分数，就地打开对应模型的回答、rubric、评分理由、问诊及纯文本／JSON 数据。未完成或限流的结果不显示假分数。

**Read saved materials and historical results** 下的材料可以在线阅读，另可下载副本。原先 **Interview study** 的历史对照保留在这里；它不再是独立主导航。

## 4. 历史问诊资料

当前网站不提供新患者问诊入口。既有八例问诊、六轮提问、事实释放记录及历史评分继续保留在 **Case review** 的历史材料中。

## 5. 人工复核和导出

- 在 **Review first** 选择一份或多份回答，按顺序分别评分。先保存问题表征 D3a，再查看信息获取 D5c 的资料；页面明确显示当前回答和步骤。全部所选回答保存后，点 **Compare all reviewed answers**，并排查看 **Your rating** 和 **AutoRubric score**。AutoRubric score 指评分模型对同一份回答给出的分数；表中同时标明回答模型与评分模型。此前已看过自动分数或模型身份时，应如实记录。
- **Clinical decisions** 用于记录某项信息是必要、有帮助还是不需要，以及可接受替代、最晚提问时点和理由。浏览到候选清单不等于已经确认，只有完成实际判断后才能记录 confirmed。
- **Export** 汇总简版材料、空白复核表、完整 raw 输出，以及可用的 TXT、JSON、CSV。需要对方独立评分时，发病例、任务、回答和空白表，避免提前给出机器判断。
- 新结果保存在本机 `arena/.data/public-access/records/members/`。公开下载会去除历史姓名标注；原始研究档案和旧结果保留。

## 6. 电脑睡眠、重启或出现 offline 时

| 情况 | 怎么处理 |
| --- | --- |
| 电脑、后端和隧道一直在运行 | 直接打开网址、登录并使用；不用重新启动服务 |
| 页面显示 **Evaluations offline** | 在主机双击启动器，等待 **READY** 后刷新网站 |
| 网络暂时断开或电脑从睡眠唤醒 | 恢复网络后稍等并刷新；仍未恢复时再次双击启动器 |
| 电脑重启 | 登录这台 Mac 后双击启动器；后端和隧道会一起恢复 |
| 隧道进程退出，地址变化 | 恢复服务会自动重建并登记新地址，不需要改设置 |
| 两分钟后仍显示正在恢复 | 后台仍会重试；检查网络、VPN或防火墙，再次点击启动器是安全的 |
| 显示配置、结果目录或 Python 环境缺失 | 先恢复原文件或原路径，不要重新运行账号初始化；结果不会被启动器删除 |

离线时，保留登录 Cookie 的浏览器也可继续查看公开研究。**Recent evaluations** 可能暂时为空，因为本机私有记录不可读取；这不表示结果被删除，后端恢复后刷新即可。

电脑睡眠、关机或断网期间，不能进行新评估或保存复核。要让他人在线评估，请保持电脑醒着并联网。中断的模型任务不会自动重跑；恢复后打开原评估，用 **Retry** 继续。

启动器只检查网站、后端配置和已发布研究是否可访问，不会调用模型或消耗评分 token。后续 KCL 请求若返回 500、超时或并发限制，仍需在该评估中使用 **Retry**。

需要排查时，查看本机私有目录中的 `recovery-status.json`、`recovery.log`、`backend-recovery.log` 和 `tunnel-recovery.log`，不要直接将这些日志或配置上传。运行 `./run-ui.sh` 只会启动原本机界面 `http://127.0.0.1:8765`，不能代替公开网站的恢复启动器。

## 7. 分享和保存

- 只看研究结果：发公开网址即可。
- 需要在线复核：私下提供相应复核账号，并指出要看的病例或批次。
- 需要调用模型：由获准的评估账号操作，同时保持主机、后端和隧道运行。
- 需要保存到 GitHub：先检查导出内容，再同步选定的公开实验和验证材料。`.env`、`ACCESS.txt`、`config.json` 和整个 `.data` 私有目录不上传。

部署方式和已验证的行为见 [部署说明](README.md)、[首次公开部署验证](../validation/20261026-public/README.md) 与 [一键恢复验证](../validation/20261027-recovery/README.md)。
